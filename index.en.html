YOUR PHONE. MORE POSSIBILITIES.

Runs natively. No root required.

Apps run on your phone’s own Android system. There is no second operating system to boot and no CPU instruction emulation.

01 / NO ROOT

Keep the phone you know.

App spaces, Alo controls, and in-space memory tools work without root. Window features require their own permissions; some display modes need ADB or wireless debugging.

02 / NATIVE EXECUTION

No virtual machine. No emulator.

Orbit uses the real device’s system and hardware, without a full virtual OS or CPU emulation layer. Compatibility work can still add overhead; performance depends on the app, device, and enabled features.

TIKTOK / NO SIM

POSSIBILITIES / APP LOCK

Decide who can open an app.

Authentication, schedules, and access rules at launch and takeover could form an app lock. This is an extension concept, not a validated finished feature.

FOUNDATIONS + EXTENSIONS / ACTIVITY AUDIT

TERMINOLOGY

What does “Shadow Mode” refer to?

This site calls the original product’s “Shadow Mode” the native system-call compatibility layer: system-call interposition, path and procfs view projection, and file-descriptor semantic adaptation. Native-code integrity and consistency across interfaces are properties that require separate validation.

System-call interpositionProcfs view consistencyFD / OFD semanticsNative code integrity

Seccomp-BPF is a system-call filtering mechanism, not a full virtual machine or complete security sandbox. This does not claim an independent kernel mount namespace. Linux Seccomp · proc(5)
