Public validation summary

Reviewed October 31, 2026. This page summarizes existing project validation records for public use. Raw logs, device serial numbers, account information, and internal archives are excluded. Record identifiers support collaboration discussions; original artifacts are not published with this site.

Historical passes apply only to the recorded builds, app versions, devices, and scenarios. Build success, startup success, model-task success, and complete business-flow success are tracked separately and are not interchangeable.

The device was a Xiaomi tablet, model 24018RPACC, running Android 16 / API 36 at 3048×2032 in landscape. At the user’s request, the latest verified de35 all-in-one ARM64 test delivery was installed over the existing app with data preserved. This is not a promise of stability for every app. Showcase spaces 80/81 were added; original space 0 was retained.

Native-task full-screen takeover returned success, but Weibo content on the right was clipped, so visual acceptance failed. Fixed-canvas takeover and resume succeeded; the initial portrait page kept its proportions with side bars. This does not establish native landscape fill for every page.

Popular apps: sample selection and three cold starts

The project uses a fixed 50-app test set. The first 30 come from the March 2026 AppInChina Android App Index; entries 31–50 are additional productivity, travel, banking, and AI samples, not MAU rankings. This site does not present that historical sample as a current leaderboard.

2026-08-31：release edf9891, Google APIs ARM64 Android 17 / API 37, 16 KB AVD. Each app had three physical and three container cold starts, observed for 8 seconds each. These records do not guarantee sign-in, payment, messaging, playback, complete business flows, or long-term stability. Third-party names identify test subjects and do not imply partnerships or endorsements.

Representative scenarios: evidence levels

“Model task” means an actual model called tools to complete the flow. “Framework validation” means deterministic control or protocol checks. “Device / UI validation” does not automatically establish autonomous model execution.

  • Find a restaurant. Plan the walk. Read actual business details, match the place in Maps, preview a walking route, and return to the original listing. Scope: model task passed on Xiaomi 12 / API 35.
  • One topic. Multiple perspectives. Search both apps for the same topic, read visible results separately, and preserve source attribution and the original search state. Scope: model task passed on Xiaomi 12 / API 35.
  • Three windows. Separate sessions. Hold independent sessions and displays at once. Stop one app while the other two remain observable and controllable. Scope: model task passed on Xiaomi 12 / API 35.
  • Take control when you need to. Take over an app through a fixed canvas, small window, or native task. Hand it back to resume agent control; old snapshots become invalid. Scope: framework checks passed on Xiaomi 10 / 12 and API 37.
  • From unknown values to one target. Device tests in a controlled native memory region covered 2,099,200 candidates, including scan undo, write undo, and saved recipes. Scope: device / UI validation on API 35 / 37, not a full-process performance benchmark.
  • One instruction. A verified memory task. A local model uses MCP to refine and undo, recover frozen values after interference, resolve module-anchored pointers, and clean up sessions. Scope: model tasks passed with owned fixtures within a limited range.
  • Control web and native interfaces. Enter text, submit forms, toggle switches, scroll lists, and locate elements after recomposition across both interface types. Scope: model tasks passed with owned test apps.
  • One task stalls. The rest continue. Keep the source app’s session and search state when a second app is not ready. Attribute errors and clean up per app without spreading failure. Scope: failure-isolation task passed, not a 12306 business-flow pass.
  • Bring Android into your tools. External clients discover capabilities, read interfaces and screenshots, click, type, scroll, and verify rejection of stale sessions. Scope: protocol / framework validation recorded by transport and environment.

The Dianping-to-Maps restaurant task returned a 2-minute / 120-meter walk in that historical run, not a live recommendation. Another coffee-shop case transferred data but found no matching map POI and was recorded separately as a framework pass. These cases do not establish acceptance of cross-app clipboard, file handoff, or notification workflows.

Memory editing and agents

Owned fixtures on Xiaomi 12 Pro / API 35 and API 37 have records for exact search, refinement, writing, reading back, and closing sessions. On API 35, a local model passed MCP refine-and-undo, HTTP module-anchored pointer, HTTP freeze, and the fixed stdio freeze tasks.

Unknown-value scanning in a controlled native region covered 2,099,200 candidates and verified refinement of a change at the end of the region plus scan undo. This is not a whole-process benchmark for arbitrary games. Single-level module-anchored resolution is not arbitrary multilevel reverse pointer scanning. Capabilities target authorized processes inside the container, not server-side values.

Records: 2026-10-07-memory-agent-matrix; 2026-10-08-memory-search-parity.

Location, VPN, and traffic capture

Location scenes cover location queries / callbacks, Wi-Fi, cells, and selected GNSS / NMEA interfaces. Connectivity state, DNS, and VPN paths remain real; location simulation does not change network egress location. VPN routing uses the shared network path, without a promise of a dedicated VPN exit for each virtual app.

Capture observes traffic within virtual app processes; it is not device-wide VPN capture. Android 13 / 15 devices and an API 36 AVD have recorded DNS, HTTP/2, and QUIC samples plus successful HTTPS requests. API 36 also has TLS event records. Protocol events do not imply all encrypted content can be decrypted; coverage depends on the target protocol and integration path.

Startup fixes exist for specific devices and versions of ICBC, WeChat, Alipay, Instagram, and other apps. They do not guarantee every protection scheme or latest release. At this review, HSBC Hong Kong and Diandian Chuanshu still have unresolved scenarios.

SIM-free TikTok use is a target scenario shown on this site. This review found no end-to-end pass record, so it is explicitly pending dedicated validation. Location and network configuration capabilities do not establish business-flow success.
